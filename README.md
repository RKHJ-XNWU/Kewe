# Kewe（聚维）

Kewe 是一个以 Android Termux 为主要运行环境的本地大模型工作台。后端使用 Dart，前端使用原生 HTML、CSS 与 JavaScript；会话、配置和文件默认保存在本机，无需单独部署数据库或前端构建工具。

当前可用模型通道为 **DeepSeek（ds）** 与 **豆包 / 火山方舟（db）**。历史中转站通道（st / relay）已在前后端停用，本文不再提供其使用方法。

## 本次版本重点

- 推理等级在高级模式下支持 **Lv.1-999 真实拖动**，保存后写入本地持久层，刷新、重启后仍按保存值生效；滑块不再回弹或锁定。
- 豆包维度全部对话模型支持多轮反思（按推理等级执行 1-4 轮）；工具模式不进入反思循环，与 DeepSeek 行为一致。
- 机器人模型按钮常驻显示当前模型名（如 `deepseek-flash`），无需点开选择器即可确认；切换模型后即时更新，完整名称保留在悬停提示中。
- 推理弹窗两端说明随中文、英语、日语、韩语、俄语、法语实时切换，不再残留“固定 Lv.999”。
- 左上角新增游戏化最大输出选择器：**64K / 128K / 256K / 384K**。
- 默认 **384K（384,000）**；选择结果由后端持久化，并应用到对话模型、续写请求与模型能力目录；模型上限优先（取档位与上限的较小值）。
- 用户规则优先于上游二进制：角色扮演（charter / character）模型固定 **32K=32,000**；Doubao-Seed-2.0-lite 与 Doubao-Seed-2.0-mini **上限 128K=128,000**；Doubao-Seed-2.0-turbo、GLM-5.2 与 Doubao-Seed-2.1 lite / Pro / turbo / Evolving **上限 256K=256,000**。上限模型实际发送 = min(所选档位, 模型上限)，允许更低。
- 模型特例由「固定值」改为「最大上限」：2.0-lite / 2.0-mini ≤ 128K，2.0-turbo / GLM-5.2 / 2.1 lite・Pro・turbo / Evolving ≤ 256K，实际发送取所选档位与上限的较小值；角色扮演仍固定 32K。
- Kimi 系列（kimi-k3 / kimi-k3.1-pro 等）强制 temperature=1.0；非 Kimi 模型完全沿用原有温度逻辑。
- 未登录访问任何页面或深链统一返回 404 错误页，仅放行登录页与其最小资源；登录后才可访问全部页面。
- 账号菜单拆分为「退出登录」与「注销账号」：退出登录只清除当前会话 Cookie，账号、聊天、知识库与文件全部保留；注销账号才会删除数据。
- 移动端性能模式：关闭全站持续旋转/粒子/网格动画，仅保留静态氛围；流式正文不再触发逐字符翻译扫描，点击与滑动保持流畅。
- 新增实时上下文控制中心：顶栏紧凑指示器、动态占用环、消息数、字符数、剩余空间、当前模型和上游 usage 展示。
- 全站视觉系统重构：统一色彩、排版、间距、圆角、阴影、卡片、按钮、表单、弹窗与交互动效。
- 针对桌面、平板、手机和窄屏分别优化布局，支持安全区、动态视口和减少动画系统设置。
- 中文、英语、日语、韩语、俄语、法语六语资源全部规范化：每种语言 **2042 个键**，键集合一致、无重复注册。
- 新增可复现的六语、输出档位和 HTTP 冒烟测试工具。

> 全站统一使用自定义十进制 K：**1K = 1000 tokens**。上下文窗口为 **1024K = 1,024,000 tokens**；输出档位为 **64K / 128K / 256K / 384K**。输出档位表示应用发送给上游的 `max_tokens` 请求上限，不代表上游一定返回该长度。用户自定义的角色扮演 32K、2.0-lite / 2.0-mini 上限 128K、2.0-turbo / GLM-5.2 / 2.1 lite・Pro・turbo・Evolving 上限 256K 规则优先（取档位与上限的较小值）；其余情况服务商自身的模型限制、额度和截断规则仍然有效。上下文占用估算不用于计费；真实用量只采用上游响应中的 usage 数据。

## 技术栈

- Dart SDK：`>=3.0.0 <4.0.0`
- 后端：`dart:io` HTTP 服务，无第三方 Pub 依赖
- 前端：原生 HTML / CSS / JavaScript，无 npm 构建步骤
- 自动化与测试：Python 3、Node.js、Bash
- 主要运行环境：Android Termux；也可在具备 Dart SDK 的桌面环境运行

## 快速开始

### 1. 获取源码

```bash
git clone https://github.com/RKHJ-XNWU/Kewe
mv Kewe kewe
cd kewe
```

### 2. 安装依赖

```bash
dart pub get
```

项目没有第三方 Pub 包依赖，该步骤用于生成 Dart 工具所需的包配置。

### 3. 启动服务

在 Termux 的 `~/kewe` 目录中，默认基础路径与源码一致：

```bash
dart run bin/main.dart
```

显式指定基础目录和端口是更通用、也更推荐的方式：

```bash
DSH_BASE="$PWD" DSH_PORT=9999 dart run bin/main.dart
```

启动成功后访问：

```text
http://127.0.0.1:9999/
```

默认配置中的 `DSH_BASE` 为 `/data/data/com.termux/files/home/kewe`。在 Linux、macOS 或其他目录运行时，必须将 `DSH_BASE` 指向实际仓库目录，否则静态文件和数据目录不会落在预期位置。

### 4. AOT 编译（可选）

```bash
dart compile exe bin/main.dart -o app
DSH_BASE="$PWD" DSH_PORT=9999 ./app
```

`app` 已加入 `.gitignore`，不会被提交。

## 最大输出选择器

点击网站左上角的 **MAX / 384K** 按钮即可打开选择器。

| 档位 | tokens | 建议场景 |
| --- | ---: | --- |
| 64K | 64,000 | 短回复、低延迟请求 |
| 128K | 128,000 | 日常对话与中等长度内容 |
| 256K | 256,000 | 长文、复杂推理 |
| 384K | 384,000 | 超长内容、极限输出；默认最大请求上限 |

选择成功后：

1. 前端顶栏、输出核心和推理等级说明立即刷新。
2. 后端将档位原子写入 `$DSH_BASE/data/output_limit.txt`。
3. DeepSeek、豆包、预设和自定义对话模型读取同一档位。
4. 新聊天与续写请求统一使用该值覆盖旧的推理等级输出设置。
5. 模型特例优先：角色扮演固定 32K；2.0-lite / 2.0-mini 上限 128K；2.0-turbo / GLM-5.2 / 2.1 lite/Pro/turbo/Evolving 上限 256K。上限模型实际取「所选档位」与「模型上限」的较小值，允许更低。
6. 上游若仍以二进制上限拒绝请求，后端会解析错误并按十进制档位自动收敛后重试。
7. 非法档位会被 HTTP 400 拒绝；配置文件缺失或损坏时回退到 384K。

语音、图片和视频模型不显示无意义的文本 `maxOutput` 字段；四档限制针对对话模型。

## 实时上下文窗口

顶栏上下文按钮每 500ms 更新一次紧凑指示器。点击后可查看：

- 1024K 上下文容量、估算占用、剩余空间和占用百分比；
- 当前模型、消息数量、正文字符数和当前输出上限；
- 最近一次上游返回的 prompt / completion 汇总；
- 当前会话累计的上游 usage 总量；
- 手动刷新和自动定时刷新。

两类数据严格区分：

- **实时估算**：由当前已加载消息、草稿、流式内容和服务端全会话统计得出，仅用于显示上下文压力。
- **上游实测**：仅来自模型响应的 usage 字段，用于展示真实用量；没有上游数据时显示空值，不伪造计费数字。

## UI 与移动端

`kewe-ui.css` 是统一视觉层，`dsc-control-center.js` 是输出与上下文控制中心。

主要适配包括：

- 统一设计令牌、字体层级、间距梯度、按钮和卡片规范；
- 顶栏玻璃质感、消息进入动画、按钮反馈、弹窗过渡、输出核心轨道动画；
- 支持 `prefers-reduced-motion`，减少动画时不影响功能；
- 支持 `100dvh`、安全区 inset、触屏目标尺寸和移动端正文字号；
- 600px 以下使用独立手机布局，390px 以下进一步压缩控件，330px 以下输出卡片改为单列；
- 表格、代码块和长文本限制在容器内，页面不产生横向滚动；
- 不支持 backdrop-filter 的浏览器自动使用实色背景。

## 新增 API

### 获取全局输出档位

```http
GET /api/ds-chat/output-limit
```

### 保存全局输出档位

```http
POST /api/ds-chat/output-limit
Content-Type: application/json

{"tokens": 128000}
```

`tokens` 只接受 `64000`、`128000`、`256000`、`384000`；旧版二进制保存值会在读取时自动迁移。

### 获取会话上下文统计

```http
GET /api/ds-chat/context?sessionId=<会话ID>&dim=ds&model=<模型名>
```

返回消息数、字符数、估算 tokens、上游 usage、累计 usage、当前输出档位和 1024K 上下文容量。

### 配置接口中的能力字段

- `GET /api/ds-chat/config`：返回 `maxOutput`、`maxOutputLabel`、`contextWindow`、`outputOptions`。
- `GET /api/doubao/config`：`catalog.forcedMaxOutputTokens` 和每个对话模型的 `maxOutput` 随全局档位实时变化。

## 故障排查

### 页面或静态资源找不到

确认启动时设置了正确的 `DSH_BASE`：

```bash
DSH_BASE="$PWD" dart run bin/main.dart
```

### 修改后浏览器仍显示旧样式

静态资源带版本查询参数。硬刷新页面，或在二次开发时同步更新 `index.html` 中相应资源的 `?v=` 值。

### 选择档位后上游仍然截断

检查上游模型本身的最大输出、套餐、余额和服务端错误。Kewe 能强制请求参数，但不能解除供应商限制。

### 上下文显示与账单不同

占用环是上下文估算，账单应参考上游 usage 与服务商账单。二者用途不同，不应直接比较。

### 数据目录权限错误

确认 `DSH_BASE` 可读写，并避免使用其他用户的私有目录。不要通过提交密钥或个人数据来“修复”权限问题。

## 安全说明

- 不要在源码、README、Issue 或提交历史中写入 API Key、GitHub Token、Cookie 或个人隐私数据。

- 上游模型可用性、额度和内容限制由对应服务商决定。
